日期：2026-11-08（Asia/Shanghai）。本轮用户明确授权：优先解决单 BIN 经小米运动健康通信身份；若不能成立，采用「快应用 RPK + 表盘 BIN」，完成录音、完整回听与无线导出成品。此前文档中「尚未接受额外身份组件」记录的是先前授权状态，不再代表当前交付限制。

## 有界复核结论

**当前没有可验证的入口，能让本项目单 BIN 独立登记 MiFitness 应用身份；本轮没有足以改变这一结论的新契约。** 这是现有公开契约与固定 P65 参考固件证据的范围结论，不是对所有未来固件的断言。单 BIN 不能被标为无线导出成功。

- 此前官方契约核查（历史研究记录，不随产品源码分发） 已核对当前第一方 SDK 1.4、demo 与 interconnect 文档：配套 RPK 安装、应用是否安装和手机授权是独立条件；未提供 BIN 自有包名、证书与安装生命周期的登记入口。
- 此前固定固件身份研究（历史研究记录） 将 `get_appinfo` 连到 PackageManager 已安装应用向量。`quickapp_register_app` 的已证作用是建立运行上下文，不能据函数名当成安装身份登记。
- 此前有界 AP 回放与既有 25 项报告（历史研究材料，不随产品源码分发）执行真实拒绝、20 字节指纹比较与组包分支；缺 AppInfo 时两向均拒绝。AppInfo 查询结果和收发终点是替身，报告明确为 `registration_verified=false`、`identity_registration_proven=false`、`single_bin_mifitness_export_proven=false`。这些通过项证明身份门槛实际存在，没有证明其登记入口。
- 此前系统录音同步复核（历史研究记录） 没有取得第三方录音登记、独立 APK 接收和持久化确认的完整契约，不能替代上述身份缺口。

本次仅复核这些已有资料、测试源码与既有报告；没有重新执行 AP、操作设备、读取私钥或录音，也没有修改生产代码、系统目录、安装数据库或身份检查。继续单 BIN 研究的有效触发条件是取得可核对的身份登记接口及更新、卸载、冷启动生命周期；不继续猜未知函数或命令。

## 现在采用的架构

**采用用户已授权的 RPK + BIN 路线，无需再次确认。**

| 组件 | 职责 |
| --- | --- |
| 录音表盘 BIN | 用户启动录音，暂停/继续、保存、录音列表、完整回听，以及完整录音导出 |
| 同包名、同签名的连接身份 RPK | 提供 MiFitness 已安装应用通信身份；不负责录音，首次安装后日常不必打开 |
| 手机 APK | 经运动健康 SDK 接收，校验整条音频并持久化，返回保存确认，提供完整回听、分享和另存 |

通信继续复用既有 MiFitness / `uv_miwear` 路径与 [w6r1 协议](WIRELESS_EXPORT_PROTOCOL.md)。录音和本地完整回听由表盘完成；不将已失败的单 RPK 录音探针恢复为产品录音入口。

## 成品验收边界

该架构已经具备代码与主机验证基础，采用它不等于当前候选已通过实机验收。交付必须同时证明：

1. 表盘实际录到完整音频，保存后能完整回听，尾音、暂停继续与连续下一条正确。
2. 身份 RPK 保持安装但日常不打开时，表盘可通过运动健康与本项目 APK 建立真实双向会话。
3. 手机收到整条音频，经长度及整文件校验完成持久化后才返回成功；手机可完整回听并另存。
4. 断线或确认丢失后能恢复，校验失败与传输失败不伪报成功，手表原音始终保留。

主机模拟、指纹分支回放、页面可点击、SDK 连接状态或 RPK 可安装，都不能单独代替以上真实录音、完整回听与无线导出结果。
