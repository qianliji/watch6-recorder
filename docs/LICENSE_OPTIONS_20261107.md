# 独立录音项目的许可证选择

核对日期：2026-11-07。本文核对了现有 `LICENSE`、`NOTICE.md` 和 `docs/IP_REVIEW.md`。**当前并不存在“调用原生接口，所以原创代码不能用 MIT”的结论。** 用户此前已明确选择 MIT，本次只是询问替代方案，因此没有修改许可证。

## 对这个项目的建议

如果仍希望别人方便使用、修改和集成，**有权授权的原创录音核心继续用 MIT 即可**。若希望对后续贡献增加明确的专利授权规则，可考虑 Apache-2.0。只有当目标变成“分发修改版时也必须向接收者提供对应源码”，才优先考虑 GPLv3。选择取决于希望授予使用者的权利，不能作为清除第三方权利问题的手段。

| 选项 | 适合的目标 | 主要条件与本项目含义 |
|---|---|---|
| MIT | 简短许可，允许广泛复用和商业集成 | 保留版权及许可声明。没有要求分发衍生版本必须开放源码；不替项目授予第三方固件或 SDK 权利。[OSI MIT 正文](https://opensource.org/license/mit) |
| Apache-2.0 | 允许商业集成，并希望有明确的贡献者专利许可及通知规则 | 第 3 条的专利许可只覆盖贡献者有权许可且符合条款的权利要求；再分发保留许可、相关声明、修改说明和适用 NOTICE。它不保证项目不会侵犯其他人的专利。[Apache-2.0 第 3、4、6、7 条](https://www.apache.org/licenses/LICENSE-2.0) |
| GPLv3 | 希望受 GPL 覆盖的衍生作品在分发时继续给接收者相应自由与源码 | 分发修改版和目标代码时应遵守第 5、6 条，包括相应的对应源码；不是所有独立并放在同一包中的程序都自动变成 GPL。实际组合、链接和 SDK 条件需另核对。[GPLv3 正文，OSI 收录的 FSF 许可](https://opensource.org/license/gpl-3.0) |

Apache 官方 FAQ 说明 Apache-2.0 与 GPLv3 兼容、与 GPLv2 不兼容。但这不表示可以把已收到的 GPL 代码任意改成 Apache 或 MIT，也不表示任意厂商 SDK 都能加入 GPL 发行物。[Apache 许可 FAQ](https://www.apache.org/foundation/license-faq.html#GPL-compatibility)

## 为什么换协议不能解决当前的授权未知项

许可证只能授予许可人有权授予的权利。改成 Apache 或 GPL 不会让来源未知的打包器、未确认可再分发的厂商 SDK、商业固件或其原生装载入口自动获得授权。GPLv3 第 12 条也没有允许忽略其他义务；无法同时满足相关条件时，不能以换成 GPL 为由继续分发。[GPLv3 第 12 条](https://opensource.org/license/gpl-3.0)

GPLv3 第 3 条涉及覆盖作品自身的反规避权利安排，**不能理解成对第三方厂商软件和技术措施的通用豁免**。在中国，具体模块装载是否涉及著作权法保护的技术措施，仍应依据实际流程和适用规则判断；个人研究和公开提供工具也需区分。[《著作权法》第 49、50、53 条，国家版权局](https://www.ncac.gov.cn/xxfb/flfg/flfg_532/202103/t20210309_50530.html)

正常录音、本地播放和用户明确发起的文件导出，本身不是上述判断的替代对象。应核对它们采用的具体代码和装载/通信方式，不能因为“原生”两个字直接断定违法，也不能因为功能正常就保证全部实现与分发已经获权。

## 本项目继续采用的分层处理

1. **原创核心、录音清单、WAV 工具及新编写的播放/导出控制**：保留来源记录，对有权许可的文件继续适用当前 MIT。
2. **直接复制的第三方开源代码**：保留原作者和原许可；逐项处理兼容性、NOTICE、修改说明或源码提供义务，不用项目根目录许可证覆盖。
3. **小米 SDK、商业固件、来源未核清的外部打包器**：继续外置。即使 SDK 未放入公开源码 ZIP，最终 APK 是否允许捆绑再分发仍要按实际 SDK 条款核对。
4. **P65 固件适配与装载方式**：保留指纹校验与完整实现记录，不能把测试通过当作厂商授权。设备候选与通用核心分开标注，发布前按 `IP_REVIEW.md` 核对未知项。
5. **未来更换许可证**：先确认各文件作者/权利人及已接收贡献的许可范围；不能替无权代表的贡献者重新授权。已按旧许可合法取得的旧版本也不会因后续改动自动失去原授权。

当前建议是：**继续完成录音、回听与手机导出，原创代码保留 MIT；不要为了“避侵权”临时换成 GPL。** 若用户明确更看重贡献者专利条款，再对权利明确的新版本讨论 Apache-2.0，而不是现在擅自改许可。

## 与本次功能实现有关的官方接口事实

- Vela 官方 JS `audio` 提供播放、暂停、停止、进度和结束事件；该页面不证明 Lua 表盘或某个 Watch 6 固件具备相同调用入口。真实实现仍要核对本机适配与固件 ABI。[官方 audio 文档](https://iot.mi.com/vela/quickapp/zh/features/other/audio.html)
- 官方 `interconnect` 要求手机伴侣与快应用的包名及签名一致。独立手机伴侣使用新包名时，需要对应身份和首次授权，不能直接假定原 VoiceSpace 身份属于新应用。[官方 interconnect 开发注意事项](https://iot.mi.com/vela/quickapp/zh/features/network/interconnect.html)

这些资料用于确定实现和许可核对范围，不构成厂商对本项目原生适配的背书。本次许可证核对没有改变 `LICENSE`，也没有公开上传仓库；具体功能改动与候选签名见对应构建报告。
