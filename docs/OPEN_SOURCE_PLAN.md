# Watch 6 录音独立开源方案

核对日期：2026-11-07。范围：当前项目源码、官方 Vela/openvela 文档及 GitHub 发布要求。本文区分代码已经具备的能力、推荐的发行基线与仍需实机确认的内容；没有公开上传代码或对设备执行操作。

用户后续提出的实现路径与侵权问题，另见 [实现与公开发布风险核对](IP_REVIEW.md)。该补充区分源码事实、法规要求与未知授权，不把 MIT 或“未发现刷写固件”当作不侵权保证。

## 结论

适合拆成 **Watch6 Recorder：本地录音核心＋独立录音界面＋固件适配层**，以 MIT 许可开放本项目有权授权的源码。它应能被其他开发者复用，也应给普通使用者提供清楚的兼容说明与可取出的录音文件。语音识别、翻译、电脑输入和云端账号不属于这个项目的基础依赖。

第一版应定位为**特定固件的原生录音适配项目**。不要命名或宣传为“所有 Watch 6 永久解锁录音权限”。小米官方 `@system.record` 的支持表目前仍把 REDMI Watch 6 列为不支持；这说明公开 JS 接口的产品支持情况，不能据此推断硬件没有麦克风或原生系统不能录音。[小米录音接口与产品支持表](https://iot.mi.com/vela/quickapp/zh/features/system/record.html)

如果独立版目前仅能在手表落盘、尚未完成回听和面向普通用户的文件传出，应先发布 **开发者预览版**。主机上的 WAV 合成工具是有用的开发工具，但不能等同于“手机已能收到录音”。

## 1. 当前录音方法到底是什么

当前本地证据来自 `watch-native/continuous-native/p65-media.c`、`native-source.c`、`profile.py`、`profile.json`、`p65-owner.c`、`p65-fs.c`、`spool.c`，以及 `watch-native/BUILDING.md`。

| 部分 | 当前代码事实 | 对公开项目的意义 |
|---|---|---|
| 采音 | 通过已固定的原生函数地址调用 Capture/RPMSG，处理准备、开始、暂停、停止和数据读取 | 不是在 JS manifest 多加一项权限即可获得的能力 |
| 固件 | profile 固定 P65 `3.100.043`，构建校验 AP/audio SHA，运行前还校验函数窗口 | 型号相同不代表地址和 ABI 相同；未知固件必须拒绝运行 |
| 核心 | `spool` 的采音状态、空间保护和分段账本可与设备调用分离 | 适合做可复用模块，单独做主机故障测试 |
| 数据 | 原音是 PCM 分段；结束和文件清单需真实落盘与校验 | “结束按钮已点”与“录音保存完成”必须是不同状态 |
| 进程 | 原生任务拥有采音；事件回调不负责 UI、文件操作或销毁；退出需确认任务和回调安全 | 不能通过强行卸载仍在运行的代码来修复卡住 |
| 验收标记 | 连续录音 profile 仍明确保留 `continuous_verified=false` 及实机验收缺项 | 构建成功、ARM 模拟通过不能替代新独立版的设备验收 |

openvela 的公开原生头文件包含录音打开、准备、开始、暂停、停止、关闭及数据读取等接口，但本项目在商业固件里使用的固定地址调用、模块装载环境和权限条件不能由该头文件推出。上游还指出 buffer 读取存在阻塞语义，这也是采音不能放在 UI 回调里的依据。[openvela media_recorder.h](https://github.com/open-vela/frameworks_multimedia_media/blob/dev/include/media_recorder.h)

据此可以说“本项目为列出的固件提供录音适配”；不能说“安装一次即可为任何版本授予系统录音权限”，也不能保证官方应用商店接受这种装载方式。本次没有找到后者的官方授权或产品兼容承诺。

## 2. 建议的拆分

```text
录音界面
  └─ 录音核心：开始 / 暂停 / 继续 / 停止 / 状态 / 文件清单
       ├─ 存储：分段、校验、恢复、空间预算、WAV 导出
       └─ 设备适配：精确固件指纹、采音调用、任务与回调生命周期

可选文件传出模块：手机中继或其他已验证文件传输方式
```

对调用者保持少量操作，把准备、尾音排空、保存和恢复放在模块内部处理。设备地址只存在于固件适配目录，不散布到 UI；存储格式有版本号，不把真实用户路径、配对身份或云端设置嵌入模块。云端转写可以由别的项目接入，录音核心不等待它。

建议分两种使用方式：

- **开发者**：使用源码与主机测试，按自己的合法固件输入构建，复用采音模块。
- **普通用户**：先查兼容表，再安装对应发行包；通过已验证的传出方法取回 WAV，不需要自己准备云端密钥。

这两类用户的前提不同，README 应分别说明，不能把研究构建步骤放在普通用户的“装上即用”说明里。

## 3. 第一版必须优先做的基础功能

以下是发行基线建议，不表示独立项目此刻已全部实现。

| 优先级 | 功能 | 可验收的结果 |
|---|---|---|
| P0 | 明确开始与准备状态 | 点击开始后显示准备；成功收音后才正式计时，失败有可执行提示；打开表盘、重连或恢复状态不自动启动麦克风 |
| P0 | 暂停／继续 | 同一条录音内暂停、继续；依据原生确认更新状态，连点不会创建第二个采音任务 |
| P0 | 结束并保存 | 停止采音、接完尾部数据、同步原音和清单后再显示“已保存”；不把超时当成功 |
| P0 | 原音和文件清单 | 每条显示编号、时长、大小、完成／中断状态；已保存录音不因下一段录音而被覆盖 |
| P0 | 文件传出与校验 | 断线可继续，传出有长度／CRC 或哈希校验；未经接收端确认不得删除手表唯一副本 |
| P0 | 标准音频导出 | 导出 WAV 可被通用播放器打开；分段顺序正确，无重复段，无无声截尾；暂停间隔的处理规则明确 |
| P0 | 空间和低电量保护 | 按实际剩余空间留尾部及元数据余量；容量不足时尽量封存已录部分，说明原因，不用设备标称容量估算可用空间 |
| P0 | 中断恢复 | 断电、退出、重启或写入失败后找回已封存片段；不伪造完整录音、不自动重新录音 |
| P0 | 固件不匹配保护 | 所有未知固件和损坏 profile 在原生调用前失败，显示“不支持此固件”，不会继续试地址 |
| P0 | 删除与数据说明 | 删除需确认，不自动清空；界面解释保存位置和传输范围；录音内容默认不进入诊断日志 |
| P1 | 回听和删除管理 | 无法在表上回听时，明确显示回听在接收端进行；不能放一个没有实际播放器的按钮 |
| P1 | 息屏与长录音 | 实测 1／30／60 分钟、息屏、切表盘、暂停继续和最后一句；每种场景单独记录支持结论 |
| P1 | 基础音质选项 | 先只开放已经验证的 8 kHz／16 kHz 单声道选项；增加编码格式前要验证固件支持及完整性 |
| P2 | 便捷功能 | 重命名、标记、搜索、压缩传输、自动归档；不抢占原音可靠保存与导出的开发顺序 |

小米官方文档列出通话、闹钟等音频焦点事件可能中断录音；因此中断处理应有明确状态和保留策略，而不只是测试正常结束。该说明不能直接当作当前原生适配的行为保证，仍需实测。[官方录音中断说明](https://iot.mi.com/vela/quickapp/zh/features/system/record.html)

## 4. 推荐发布顺序

### 开发者预览版

提供录音核心、精确适配 profile、主机测试、离线 WAV 合成工具和构建说明。明确标识表上回听、文件传出、息屏或长录音中哪些尚未验收；没有通过的项目不显示为“支持”。不捆绑厂商固件，也不以现成固件二进制替代可构建源码。

### 面向普通用户的首个测试版

在至少一台列出的真实固件完成 P0 验收，尤其是“录下来、取出来、播得完”。提供版本对应的安装包、SHA-256、安装／卸载说明、已知问题及可回退版本。GitHub Releases 适合把某个 tag 的说明和可下载文件放在一起，避免用户混用不同版本的源码和包；本项目仍需自行提供文件校验和与验收记录。[GitHub Releases 说明](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)

### 多固件社区适配

每个新增固件提交单独的 profile、合法输入来源说明、构建测试和设备验收。不能只改一个版本字符串或关闭 guard 就并入支持列表。完整固件、用户录音、配对数据不作为 issue 附件上传。

## 5. 兼容矩阵怎么写

至少记录这些列：设备型号／产品代号、地区或硬件变体（确认相关时）、完整固件版本、AP/audio SHA、项目版本、构建状态、真机短录音、暂停继续、息屏、长录音、完整尾音、文件传出、WAV 回听、已知冲突。

目前可确认的是：现有录音适配代码针对 **REDMI Watch 6／P65／3.100.043 的指定镜像指纹**；独立版的新文件位置、UI、生命周期和导出流程仍必须单独验收。其余固件写“未适配”，而不是笼统标成“Watch 6 支持”。不要因为模拟通过而把真机列打勾。

## 6. MIT 的范围与第三方来源

用户已选择独立录音项目使用 **MIT**。根目录 `LICENSE` 应采用规范文本，并由项目权利人确认公开署名；可用项目署名 `Watch6 Recorder contributors`，不必公开私人姓名或联系方式。MIT 允许他人商业使用、修改和再分发，要求保留版权与许可声明，并不要求其衍生项目也开源。[MIT 规范文本](https://opensource.org/license/mit)、[GitHub 的 MIT 填写说明](https://choosealicense.com/licenses/mit/)

MIT 只能授予项目所有者有权许可的部分，不能覆盖他人的 SDK、固件或已有许可。VoiceSpace 全量源码与这个独立模块是不同发行范围，前者的许可证状态不能自动改变。GitHub 也明确指出，公开仓库本身不能代替开放源码许可。[GitHub 仓库许可说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)

| 内容 | 发布建议 |
|---|---|
| 自己编写或有权授权的录音核心、UI、存储代码与测试 | 纳入独立项目 MIT 范围，保留作者来源记录 |
| 来自现有项目的文件 | 在 `SOURCE_PROVENANCE.json` 记录来源路径、基线版本、改动和授权范围；移动文件不等于重新取得版权 |
| openvela 头文件／实现直接摘取的代码 | 按原 Apache 2.0 许可保留原版权、许可与适用 NOTICE，标记修改；不能只替换成 MIT 头 |
| 固件 ABI 地址、指纹和 profile | 与原音频框架源码分开标注；它们用于适配，不等同于获得整个商业固件的再分发权 |
| 小米 SDK、JAR、固件镜像、固件提取产物 | 当前不放公开源码包；构建者按适用条款自行取得合法输入 |
| 表盘 Java 打包器 | 当前文件提到 `Android_Source/WfWriter`，需要补齐来源、原许可证和改动映射；“project-owned repair”的注释本身不能证明整个文件来源已清晰 |
| GNU Arm、JDK、Python 第三方包 | 写入构建依赖和版本清单；不把本机工具安装目录一并打包 |

openvela 多媒体仓库声明 Apache 2.0；Apache NuttX 的 `LICENSE` 还列有具体第三方内容，不能只看项目名就把全部文件统一换成 MIT。实际复制了哪些文件，就逐项保留对应的许可和声明。[openvela 多媒体许可](https://github.com/open-vela/frameworks_multimedia_media/blob/dev/LICENSE)、[Apache 2.0 再分发条款](https://www.apache.org/licenses/LICENSE-2.0)、[NuttX LICENSE](https://github.com/apache/nuttx/blob/master/LICENSE)

上述来源核对不是对商业固件分发、设备条款或当地法律作出授权判断；目前没有足够的一手材料作出这种结论。

- 安全报告使用维护者明确设置的渠道或 GitHub 私密漏洞报告；不能留下虚构的个人邮箱。`SECURITY.md` 应说明支持版本和报告方法。[GitHub 安全政策说明](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/add-security-policy)

## 8. 最小测试与 CI

公开 CI 默认只用合成数据，不需要云端密钥、真实录音或厂商固件。把固件相关构建作为维护者自备合法输入的单独流程，报告结果时区分“源码可测试”“设备包可构建”“真机验收通过”。

必须覆盖的自动化断言包括：重复点击只建一个任务；准备失败不计时；暂停／继续有确认；停止后尾部只入库一次；写入短写／空间不足不丢已封存段；进程中断后可恢复；损坏段被识别；WAV 长度与 PCM 数量一致；不能覆盖现有导出；路径穿越被拒绝；未知固件不启动；新项目源码和公开 ZIP 无密钥／签名／个人路径／固件镜像。

设备验收至少包含短录音、30 分钟及 60 分钟、息屏、切表盘、来电／闹钟冲突、暂停继续、低空间、传输中断续传、尾音和回听。录下的数据量、时长、可播放结果与失败原因都应留存脱敏结论，不使用真实会议内容作公共测试样本。

CI 使用最小权限、固定依赖与受审查的 action 版本，不把私密构建设置写进工作流或日志。涉及签名或发行权限的任务应与外部贡献的测试任务分离。[GitHub Actions 安全加固](https://docs.github.com/en/actions/how-tos/security-for-github-actions/security-guides/security-hardening-for-github-actions)

## 9. 当前不能对外承诺的内容

- 所有地区、硬件变体和未来固件的 Watch 6 均能运行。
- 开源源码会永久改变系统录音权限，或官方商店必定允许分发。
- 已证明息屏、长会议、最后一句和全部中断场景在独立版可靠。
- 表上回听与不依赖原应用的手机文件接收已经完成。
- 可公开提供商业固件镜像、厂商 SDK 或来源未核对的打包工具。
- MIT 已覆盖原 VoiceSpace 全部源码及第三方文件。

推荐的首屏表述是：“面向已列出固件的 REDMI Watch 6 原生录音适配与本地保存项目。独立录音核心采用 MIT；使用前请核对兼容矩阵。开发者预览版中尚未验收的文件传出、回听或后台场景会明确列出。”等普通用户能把一条完整录音可靠取出并回听后，再升级为面向大众的测试发行。
